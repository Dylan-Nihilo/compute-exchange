## 15.1 计划规则

### 15.1.1 需求基线与冲突顺序

按以下顺序解释需求，前者优先于后者：

1. `docs/01-14`：当前产品范围、REQ、状态机、合规红线和非功能要求。
2. `docs/13 §13.1`：已决策事项；未决事项仍作为对应 Phase 的阻塞 Task。
3. `docs/16-A0-前端业务契约.md`：当前前端路由、权限和状态机契约。
4. `docs/18-需求变更记录v1.1.md`：C-01～C-08 作为增量需求纳入；其中“已实施”只描述外部 Go 后端快照，不代表本仓完成。
5. `docs/17-P0需求追踪矩阵.md`：P0 核对辅助，不代替 P1/P2 与 v1.1 增量。
6. `docs/00`、`docs/15-需求任务拆解.md`、`docs/16-架构设计.md`、`docs/17-API接口设计.md`、`docs/api/*`、`docs/19`、`docs/20`、`docs/CR审查_PM进度报告.md`：后端参考或历史证据；不得直接继承其实现状态。

发生冲突时，资金规则以订单直付、易宝持牌分账、无现金余额为准；履约后才触发延迟分账；真实交易受三段式合规开关控制；v1 不做底层算力编排、在线融资撮合、设备在线支付、空心机房在线下单。

### 15.1.2 Phase 与 Task 约束

- 一个 Phase 只描述一个可独立验收的需求能力，不按“前端/后端”横切。
- 每个 Phase 必须声明：需求来源、范围、Tasks、完成门槛、依赖/阻塞。
- Task 是完成该 Phase 的具体工作；必须覆盖契约、界面、服务、守卫、异常状态与验证，不能只写“开发页面”。
- `P0/Must` 先于 `P1/Should`，`P2/Could` 只在全部 Must 达标且业务确认后启动。
- 第三方未接入时可完成 adapter、沙箱与失败态，但不得把 Mock、配置项或 200 空响应记为生产完成。
- 每个 Phase 关闭前更新 `docs/17-P0需求追踪矩阵.md`；需求变更先更新源需求，再更新本计划。

### 15.1.3 当前仓库基线

当前已验证存在：官网 Landing Page、HeroUI/HeroUI Pro 基建、统一前端领域契约与状态机、认证与多身份 Mock 基础、工作台路由骨架、算力市场列表/搜索/结构化筛选/分页、API client 与 59 项测试。

这只代表对应 Phase 的部分 Task 已有实现，不代表任何业务 Phase 整体验收通过。`docs/20` 所述 Go 后端不在本仓，真实 API、数据库、易宝、newapi、BSN、KYC、电子签和发票能力一律按“未在本仓验证”处理。

### Phase 02 · 统一账户与会话安全

**需求来源**：`docs/06 §6.1`（REQ-D-001～006）；`docs/09 §9.4`（REQ-G-031）；`docs/10 §10.3`（REQ-N-020～025）；`docs/13` Q-29。

**范围**：一套账户优先支持手机号、邮箱与微信登录，并提供多身份承载及安全会话。

**Tasks**

- T02.1：实现手机号短信验证码、邮箱验证码、微信扫码三种优先登录方式；统一绑定同一账户，注册后默认 buyer 身份，微信首次登录补绑已验证手机号或邮箱。
- T02.2：接入滑块/图形验证码、短信与邮件服务，完成验证码发送/校验/过期/重放防护和 IP+账号限流。
- T02.3：实现会话轮换、设备/IP 记录、全端登出、异常登录提醒和敏感操作二次验证；后置密码功能启用时补不可逆密码哈希。
- T02.4：定义账户冻结、注销、数据导出/删除申请及被阻断状态，不让冻结账号继续持有有效会话。
- T02.5：P1 后置账号密码、密码设置/找回/重置及企业微信登录；P1 支持企业子账户、成员邀请和最小角色授权。
- T02.6：将现有 Mock auth 置于 adapter 后，补真实 API 契约、失败态和鉴权/限流测试。

**完成门槛**：手机号、邮箱与微信三种优先登录，以及注册、登出、限流、会话撤销、冻结账号阻断和多身份账户契约通过安全测试；敏感信息不进日志。

### Phase 03 · KYC、企业认证与身份解锁

**需求来源**：`docs/06 §6.2`（REQ-D-010～013）、`§6.7`（REQ-D-060）；`docs/02 §2.3–2.4`；`docs/13` Q-13。

**范围**：个人/企业身份认证与 supplier/vendor/funder 资格申请，驱动实际权限解锁。

**Tasks**

- T03.1：实现个人实名三要素/人脸核验表单、授权、状态机、失败重试和最小回显。
- T03.2：实现企业认证、营业执照/法人/对公账户材料上传、OCR/校验状态及补件流程。
- T03.3：将认证状态作为下单、上架、结算入口等服务端强制门禁，前端提供明确解决路径。
- T03.4：实现多身份申请、审核结果同步和身份切换；当前角色与账户已解锁角色始终一致。
- T03.5：企业认证字段复用于易宝进件，建立字段来源、变更和重新审核规则，避免重复填报。
- T03.6：完成 KYC 供应商 Q-13 选型与 DPIA/合同/沙箱验收；原始证件加密、脱敏和访问审计。

**完成门槛**：四类自助身份均能提交、补件、通过/驳回并正确解锁；越权与认证绕过测试通过。

### Phase 04 · 运营权限、配置与合规开关

**需求来源**：`docs/08 §8.7–8.8`（REQ-F-060～073）；`docs/02 §2.4`；`docs/13` Q-04/Q-05；`docs/10` REQ-N-031、REQ-N-071。

**范围**：运营/管理员分权、用户治理、基础配置和真实交易开闸控制。

**Tasks**

- T04.1：实现 operator/admin 账号开通与 RBAC 权限点，审核、订单、财务、风控、CMS、用户、审计职责分离。
- T04.2：实现用户检索、详情、认证状态、冻结/解冻和高风险确认；记录操作人、对象、前后值、理由、IP、时间。
- T04.3：实现费率、通知模板、支付/newapi 非密钥参数和字典配置；密钥只存密管引用且不可回显。
- T04.4：实现 `showcase / limited / open` 三态合规开关、单笔/累计限额、变更审批和紧急回退。

- T04.6：P1 实现备份/导出策略配置；所有配置持久化、版本化、可审计且多实例一致。

### Phase 07 · 供给资源盘点与库存一致性

**需求来源**：`docs/03` REQ-A-012、REQ-A-023、REQ-A-043；`docs/10` REQ-N-002/N-004；`docs/18` C-03/C-05；`docs/20 §1.1` 仅作风险证据。

### Phase 08 · 算力市场发现与选型
